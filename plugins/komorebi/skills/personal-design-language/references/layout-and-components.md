# Layout and components

## Layout

- Data workspaces may use broad containers and compact rows. Forms and reading-focused content should constrain width for focus.
- Use split screens only when two contexts must remain visible together. Avoid floating elements unless they provide a clear persistent action or navigation benefit.
- Use a strict grid for structured data; relax it intentionally for editorial or campaign storytelling.

## Components

- Buttons are normal-sized and direct. Keep one prominent primary action per decision area; use text/ghost treatment for cancel and isolate destructive actions behind confirmation.
- Use icon plus text unless the icon is universally familiar. A tinted icon container is allowed when it materially improves scanning, especially in a dashboard.
- Use subtle-to-medium rounding for inputs and buttons; cards and modals are generally less rounded. Reserve pills for tags and badges, not general navigation, filters, or buttons.
- Forms use floating labels by default: the label begins inside the field, then floats at the top edge on focus or once the field has a value. It remains visible after entry; placeholders supply examples or format hints only. Toolbar search/filter controls may use a conventional visible or programmatic label with a concise placeholder instead.
- Long forms can group sections with restrained tint or separators rather than card stacks. On mobile, use one column except for genuinely linked fields.

## Navigation and data

- Choose a sidebar for deep hierarchy and persistent workspace context; use a top navigation for a small horizontal information architecture. Use breadcrumbs only when hierarchy needs recovery.
- Underline tabs are the default. A lightly tinted segmented control is acceptable for a small, peer-level mode switch, not as a universal pattern.
- On mobile, keep 3–5 high-value destinations in bottom navigation when the app warrants persistent mobile navigation. Re-prioritize content instead of merely shrinking desktop.
- Tables remain tables when comparison matters; support horizontal scroll or an intentional alternative. Convert operational worklists to cards only when each item needs a self-contained action flow.
